# GeoSaarthi Earth Intelligence Operating System

GeoSaarthi’s expanded experience is arranged as one operating system rather than twenty-five unrelated screens. **Earth observation** begins with a scene or area of interest, **mission control** transforms the observation into a validated analysis request, **specialist workflows** make the route explicit, and **evidence, trace, and report** preserve a reviewable endpoint. Each route shares the orbital, evidence-first visual language while changing its central analytical object and primary interaction.

| Route group | Routes | Shared purpose | Distinct visual centrepiece |
|---|---|---|---|
| Observe | 01, 02, 05–07, 09 | Establish mission context, location, source, and temporal state | Earth, orbital pass field, temporal strip, provenance registry |
| Analyze | 03, 04, 08, 10–11 | Define an input contract, route a task, and inspect available tools | Observation contracts, imagery canvas, history ledger, execution graph |
| Prove | 12–15, 18, 25 | Inspect supporting evidence and turn it into a reproducible artifact | Evidence map, spectral field, fusion canvas, timeline, report, replay rail |
| Operate | 16–17, 19–20, 22, 24 | Run scenarios, monitor the prototype, and prepare a fair SIH demonstration | Mission sectors, benchmark matrix, alerts, system lattice, preference plane, proof route |
| Learn | 21, 23 | Explain concepts and guide evaluators through the available interface | Learning constellation and documentation route map |

## Cross-Route Contract

Every non-landing route will present a page-specific hero, visual centerpiece, primary interaction, a state panel for loading/empty/success/error conditions, keyboard-reachable controls, and a concise statement of what is simulated, scripted, or bounded. The global command palette and the contextual route rail provide continuity, while page transitions use deliberate opacity and transform changes rather than decorative motion alone.
